MECHANISM VALIDATED (2026-07-13, ecosystem-practice agent; reconciles the fence-cost revision). Shipping precedents: PyTorch MPS (MPSEvent.mm) uses EXACTLY our mechanism — end active encoder, encodeSignalEvent mid-command-buffer with a self-maintained counter, MTLSharedEventListener block -> condvar; MLX's cross-stream Event is the same GPU-side shape (device.cpp signal_event ends the encoder mid-CB); MLX commits whole CBs every 20-50 dispatches with completion handlers and still does ~130 tok/s — so fine-grained boundaries are generically cheap. Apple docs guarantee the signal fires after ALL prior commands in the buffer complete (execution-order guarantee, independent of hazard tracking -> our untracked buffers are fine on the GPU-write->CPU-read edge). llama.cpp has NO equivalent (blocks in waitUntilCompleted every step) — the upstream PR is genuinely novel for candle.\n\nGRANULARITY RESOLUTION: per-token signal via bare encoder split right after the argmax (primary — semantics exactly cover the ring write; the CPB sweep's ~40us priced full CB boundaries incl. commit, a bare split pays only the all-fence wait, est. 10-20us = 0.3-0.6%/token); commit-piggyback remains the fallback if the production A/B shows the split. Measure, don't argue.\n\nDESIGN CONTRACT (from documented failure modes — bake into the candle PR):\n1. HOST-OWNED strictly-increasing atomic for signal values; never reset, never derive from event.signaledValue (Apple engineer guidance; forum 673294's bug was value reuse).\n2. Listener notifications are ONE-SHOT and COALESCE: the block must consume the ring up to signaledValue (not one-token-per-callback) and re-arm at consumed+1; or PyTorch-style condvar + consumer thread.\n3. Dedicated serial dispatch queue for the listener; block body trivial (read counter, wake consumer); EOS/detokenize on our own thread.\n4. EOS early-stop is a separate mechanism (signal path is GPU->CPU only): bounded encoder run-ahead K, checked against the consumer's stop flag.\n5. Upstream API ships BOTH paths: listener notify + blocking waitUntilSignaledValue(value, timeout) fallback (every runtime exposes both; ggml uses 60s timeout + abort).\nMLX datapoint for expectations: even ~200us/step of SharedEvent sync latency did not move tok/s (their PR #1869) — the listener wake (~50-150us, off critical path for us) is a non-issue. STATUS: design fully derisked; implementation can start after the quiet-machine census rerun confirms the drain-tail EV, or immediately on jitter grounds alone.

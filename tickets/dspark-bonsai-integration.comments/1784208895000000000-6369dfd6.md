Work-item 5 (verify GEMM) is the whole story: verify = 81% of round time (propose 10%, overhead 8%), so spec sits at parity (~11–12.5 tok/s) not 2–3×. FIVE verify-kernel variants measured + reverted (mc / tile-mm-BN32 / BM8-scattered / BM8-coalesced / BM64-BN8 / planar-mm2d), all bounded by the same root cause: the Q2_0 [row][block] layout can't give coalesced-cross-row reads AND matrix-unit tiles at once; the planar [k][row] repack (`q2_0_mm2d_planes`, committed) fixes coalescing (flat/weight-bound-structured) but the hand-rolled software unpack caps at 38 GB/s vs the 106 needed. The hardware fix is `tensor_ops::matmul2d` (what q4_K's mm2d uses for 142 GB/s), which needs a `uint2b_format`/`int2b_format` B operand — those exist ONLY in **Metal 4.1**, and the M3's shipped toolchain (32023.883, SDK 26.5) has only the 4-bit types (a `uint2b_format` compile fails today). 4-bit up-convert works now but doubles the target to ~13.5 GB → OOM on 18 GB. So the 2–3× is a toolchain-version gate, not a design failure.

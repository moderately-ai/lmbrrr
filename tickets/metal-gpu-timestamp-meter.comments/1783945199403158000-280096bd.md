EXECUTOR PROCEDURE — build + validate the in-binary GPU meter.

WHY: several evals in the 2026-07 wave (drain probe, deferred readback, round-3 variants) need GPU-busy vs host-gap attribution without a 30-minute Xcode gputrace cycle. MTLCommandBuffer exposes GPUStartTime/GPUEndTime (seconds, host timebase) after completion — enough to compute per-command-buffer busy time and inter-buffer gaps.

IMPLEMENT (fork, candle-metal-kernels/src/metal/commands.rs): behind env `CANDLE_METAL_TIMING=1` (OnceLock), attach a completed-handler to every command buffer at commit that appends (start, end, dispatch_count) to a global Mutex<Vec<...>>; expose `pub fn timing_report() -> Vec<(f64, f64, usize)>` + a drain/reset fn. lmbrrr side: at end of bench/run when the env is set, print total GPU busy = sum(end-start), wall = last_end - first_start, gap = wall - busy, buffers count, mean busy per buffer. Keep it OFF-path when env unset (zero overhead: a single OnceLock bool check at commit).

TRAPS: (a) completed-handlers run on a Metal queue thread — the Vec mutex is fine, but do NOT touch encoder state there; (b) GPUStartTime is 0.0 on some buffer types if the buffer did no GPU work — filter; (c) handler must be installed BEFORE commit (addCompletedHandler after commit is an API violation and panics).

VALIDATION (this is the eval): run `CANDLE_METAL_TIMING=1 ./target/release/lmbrrr bench --quantized-manifest artifacts/minicpm-v46-q4k-full-text/manifest.json --quantize-lm-head q4k --warmup 1 --iterations 1 --profile short` and check against the known trace ground truth (docs/research/metal-decode-utilization.md): a decode step spans ~3 command buffers at CPB=100, each ~0.9-1.0 ms busy, boundary gaps ~0 (post wave-3). PASS = meter reproduces: (a) per-step GPU busy within +/-15% of steady_state_ms minus the known host residual, (b) near-zero inter-buffer gaps, (c) buffer count consistent with dispatch_count/CPB. FAIL diagnostics: busy >> expected means handlers double-count re-used buffers; gaps >> 0 contradicting the trace means the timebase mixing is wrong (GPUStartTime is already host-clock; do not convert).

GATES before shipping the fork change: env-unset run byte-identical text + bench tok/s within noise vs pre-change binary (the added commit-path branch must be free); nextest 59; rebuild after nextest. Then bump the pin in lmbrrr Cargo.toml (4 rev= lines) and rebuild.

DELIVERABLE: meter merged behind env flag + a comment here with one validated report (numbers above) so later evals can trust it.
